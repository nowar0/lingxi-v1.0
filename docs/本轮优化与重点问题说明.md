### 容量是怎样生效的

1. 会话模型选择沿用原来的优先级：当前会话 → 工作预设快照 → 功能模块。
2. 用选定模型的服务地址、协议、模型 ID 查找容量。不同 Key 指向同一地址、协议和模型时共享容量设置；换到另一个服务地址或模型不会误用旧值。
3. 服务模型清单返回明确整数容量字段时，记录为“服务元数据”。支持识别 `context_window`、`context_length`、`max_context_tokens`、`input_token_limit`、`inputTokenLimit`，范围为 2048–2,000,000。不会从模型名字猜容量，也不会把字符串、布尔值当作确认值。
4. 有手动值时采用手动值；不能手动填得比服务已声明的容量更大。没有服务值、也没有手动值时才使用全局后备容量，初始为 32768。
5. 原文与检索装配、压缩阈值、摘要准备使用相同的有效容量。单独选择的摘要模型容量更小时，摘要材料也受较小容量约束。
6. 小容量模型的回复、工具、记忆预留按比例缩减，使输入保留约四分之一容量；用户保存的全局默认值不被改写。模型实际发送前还有一次容量检查，包括故障转移后的实际目标，超限则说明原因并阻止发送。

“服务元数据”表示服务声明，不等于已经向真实账号发送了极限长度请求。未知容量的模型、本地服务未暴露可识别容量的情况，仍需要根据服务设置手动填写。当前计数沿用 UTF-8 字节保守估算，不能当作模型厂商精确 tokenizer 或实际账单。

### 画布现在怎么用

1. 手动新建任务及添加、复制智能体时，节点默认不接线。复制智能体不会复制它的依赖或主调度入口。
2. 从主调度右侧端口拖到智能体左侧端口，建立执行入口。
3. 从智能体右侧端口拖到另一个智能体左侧端口，建立前置成果依赖。一个成员有多个前置时，必须等全部前置完成。
4. 选择连线后可断开，也可按 Delete / Backspace。主调度连线也可选择、断开和保存。
5. 同一个入口成员不能同时挂成员前置。要改为入口，先断开它原有的成员前置；给入口增加成员前置时，会移除它的入口关系。
6. 保存草稿允许暂时留有孤立节点，方便继续编辑。开始前必须让全部成员接入主调度工作流；孤立节点或只有部分前置可达的节点会阻止整个计划启动，并指出成员。不会默默执行或默默忽略它们。
7. 循环、重复编号、不存在的依赖、非法入口和过期修订均由后端拒绝。运行后执行计划锁定，仍可调整布局；改计划需复制为新任务。
8. 连线和位置保存后，重启仍保留。旧任务、AI 已生成计划保留原有依赖语义；编辑保存后会明确记录主调度入口。
9. 本轮只有智能体节点；模型、技能和工具仍在成员设置中选择，没有拆为独立节点。

模型清单中的“用于消息 / 用于工作”已采用紧凑的中性圆角按钮，沿用现有黑白配色、字号与边框。模型名称、能力标签、用途操作分行组织，两个用途按钮在同一操作行，避免标签挤占后零散换行。

## 6：摘要检查卡是什么，怎样实现

**现在已有：** 上下文压缩生成结构化摘要，保留完整原聊天。摘要当前有五组字段：已确认事实、持续话题、未完成事项、不确定事项、修正。会话压缩菜单可查看摘要、压缩状态与失败原因；来源变化、摘要格式不合格或失败时，旧摘要和原文保留。

**建议的检查卡表现：** 以目标、事实、限制、已完成、待办、不确定六块展示，允许展开出处。每条清楚区分用户事实、助手建议和推断；“不知道”不自动补成事实。显示摘要时间、使用的模型、覆盖到哪一轮，以及已知用量；未返回用量的部分标为未知。

**实现方式：** 从已有摘要与来源消息编号构建展示层；新增的六块需要带版本的摘要结构和兼容映射，不能仅把五个旧字段改名冒充完整六块。用户修正作为一条独立、带修订号的覆盖记录保存，下一次摘要同时带入原摘要、用户修正和新增原文。提交前检查来源是否被编辑、撤回、删除或彻底忘记；不再有效的来源不能继续当作事实。

本轮没有新增这张六块摘要检查卡，也没有新增“直接改摘要即改历史”的能力。

## 7：设置生效来源怎样显示

**现在的规则：** 会话单独选择优先；工作预设在绑定时保留快照；没有覆盖时才使用模块默认。温度、思考强度等分别解析，不能用“模型来源”推断所有参数来源都相同。会话压缩参数和消息/工作默认值也有各自保存与修订检查。

**建议表现：** 每项旁边显示“本会话”“工作预设快照”或“模块默认”，同时显示实际值；点“跟随默认”只取消这一项覆盖。例如取消会话模型覆盖，应重新按预设/模块解析模型，同时保留会话目标、计划、权限、草稿和其他覆盖。

**实现方式：** 使用后端解析结果中的实际值与来源字段绘制标记；接口支持按字段清除覆盖，仍校验修订和运行状态。不能通过提交一整份空表单来实现“跟随默认”，那会误清其他选择。预设快照需标明绑定时间/版本，不能把后来改过的预设误称已经作用于旧会话。

本轮没有另做完整的逐项来源标记与清除覆盖界面。

## 8：附件状态怎样解释

上传成功，只表示文件进入零汐资料库；能预览，只表示本地可以查看；提取成功，表示得到一段文本；加入草稿，表示等待你发送。它们都不等于文件全文已经发给模型。

**建议表现：** 每个附件依次显示“已上传 → 可预览 → 已提取多少 → 已加入草稿 → 本轮实际发送范围”。节选要标出页码、行或字符范围，不能仅显示“已读取”。文件过大、提取失败、无文本、密码保护和模型不支持的模态要分别说明。PDF / 图片等原件与提取文本是两条不同发送路径。

**实现方式：** 上传接口返回文件 ID、类型、字节数与哈希；提取结果记录来源范围、截断情况和提取器；草稿只保存引用；发送装配器生成这一轮实际使用的资料清单。确认发送后保存实际范围及所用版本，界面根据这个清单显示“已发送”，不能拿上传回执代替。资料在预览后被修改、删除或权限变化时，要使旧发送预览失效。

本轮没有新增附件状态流水线；现有上传、预览、节选、引用和发送规则继续适用。普通界面没有因为源码中存在原生视频模块而自动获得视频发送入口。

## 10：按用途选模型的实现方式

不应编造“最快”“最聪明”“最便宜”的排行。服务给出的模态声明、用户声明、资料推断、账号连接成功、真实调用成功和效果合格，是不同的证据。

**推荐实现：** 给模型保存用户用途标签，例如日常消息、编程、长文、图片理解、摘要、复核。筛选时先看真实输入输出模态和当前功能要求，再按用户标签缩小清单；给每个标签标出“用户指定”“服务声明”“本机试用通过”等来源。能力未知时明确提示，保持已有的显式选择与确认流程。

速度、价格与质量只有在有可追溯样本、测试任务、日期和相应账号条件时才展示；没有数据就不排序为结论。延迟按同一环境、同类请求统计，价格按服务当前计费配置，不能从模型 ID 猜测。一个模型适合消息，不等于它支持图片、工具或长上下文。

**与现在的区别：** 本轮修正了模型清单的消息/工作分配按钮样式；现有分配仍调用原来的真实分配接口，不是新增一套未经验证的用途推荐器。容量设置不会宣称模型的质量或费用已经验收。

## 14：最终怎样收尾，如何防止模型提前“结算”

### 当前程序真实行为

成员模型正常结束并保存输出后，该成员可以变成 `complete`。这表示这个成员本次生成已结束、有结果保存，**不代表自然语言任务的所有要求已被证明完成**。模型说“完成了”也不能替代真实工具日志、产物和验收。

所有成员完成后，整体任务进入 `review`（待验收），不是直接成为最终完成。汇总提示会要求按验收标准核对、指出缺失证据和未完成项。最终接收仍需你的明确操作；设置了独立验收模型时，后端还要求本次有效独立验收通过。

### 当前参数与判据

| 项目 | 真实参数或行为 |
| --- | --- |
| 单计划节点数 | 1–20。 |
| 标准调度同时执行 | 每批最多 3 个就绪成员；前置成果保存后才能进入后续成员。 |
| 原生成员模型工具循环 | 最多 6 轮；第六轮仍要求工具调用时会报达到上限，不无限运行。 |
| 默认独立验收模型 | 空，即未启用独立模型验收。 |
| 默认每日 Token / 媒体调用上限 | 均为 0，表示不设该项每日上限，不表示免费。 |
| 默认单次回复预留 | 4096 Token；可设 128–32768。不是保证输出长度。模型容量还会约束请求。 |
| 独立模型验收 | 3 个判据，每个交换 A/B 顺序各评一次，共 6 次模型请求，先预览再明确确认发送。 |
| 三个判据 | 需求符合、产物/实际输出相符、错误信号。 |
| 通过阈值 | 总均分至少 0.65、总分高于空白基线，且每项平均分至少 0.65。 |
| 验收证据 | 任务目标和验收标准、节点结果、真实工具证据、你明确选定文件的执行前基线与执行后差异。 |
| 证据范围 | 最多 100 个选定路径；单文件超过 256,000 字节不采集，总原始数据超过 4 MiB 拒绝；差异和发送包还各有长度限制。 |
| 预览有效期 | 10 分钟；证据、任务状态或目标模型改变后，旧预览不能当作有效通过。 |

独立裁判只核对提交给它的证据，没有亲自运行你的测试。选定文件范围之外的项目内容没有被它全部验收。低分需提供可定位的结构化问题；评分格式无效、调用失败或证据变化不能算通过。

### 模型没做完却正常停答，怎么办

这属于语义上的提前结束，程序不能仅凭接口返回 `stop` 自动证明任务完整。当前保护是让整体进入待验收，由明确验收标准、真实产物/测试证据和可选独立复核拦住最终接收。没有设置独立验收时，仍需要你核对后手动验收，不能理解为系统已经自动检查一切。

发现缺项时，不要点最终接收。成员追问适合解释和复核，**它不会继续执行工具**。需要继续修改文件或运行工具，应复制为新任务或重规划，把已保存成果作为材料，并把缺项写成明确子任务。已完成成果保留，不重做整份未知操作。

如果是连接中断、模型被截断、工具失败或结果未知，程序会保留失败/中断状态与已保存成果。原生 OpenAI 流式链路对没有正常结束标记、长度截断和不完整工具调用会报错；只读瞬时故障最多额外重试一次。未知写操作不会自动重放，须核对实际结果。

### 建议的收尾卡最终表现

建议固定显示：已完成事项、实际产物、验证结果、未完成/受阻事项、需要你处理的下一步。每项绑定任务编号、产物路径和对应证据，而不是仅生成一段漂亮的总结。模型负责提出完成主张；后端按验收项检查证据；独立模型辅助发现矛盾；你决定是否接收。

例如“修改文件、构建成功、三个分包可组装”应是三个分别有证据的验收项。模型只产出修改说明，构建没有真实退出码或组装没有校验记录时，后两项保持“未验证”。预算或轮次耗尽应显示“未完成，已保存成果”，不改成已完成。继续入口也必须区分解释、只读复核、允许修改的后续任务，不能暗中重放写入。

本轮没有新增这张完整收尾卡或通用的自动完成判定器。上述状态、阈值和防重复执行是现有机制；收尾卡属于解释的后续方案。

## 验收和使用范围

本轮修复了从链接打开记忆时首次同步校核与详情保护相互等待的问题：先建立首次只读基线，再打开目标详情；外部更新、冲突与确认保护保持有效。

本轮已检查真实 Electron 与冻结后端、独立首启空记录、设置保存/取消恢复默认、搜索、模型预算、入口断开、复制节点、依赖保存与执行顺序、重启持久化，以及 100% / 125% / 150% Electron 缩放渲染。

相关验证：前端 348 项通过，后端与智能体 62 项通过，最新实际 EXE 验收 47 项通过，未跳过相关测试；模型列表样式另经真实 EXE 截图及字号/尺寸核对。历史测试中旧“工作区写文件总要再弹确认”的前提已按当前工作区授权规则更新，仍验证真实落盘与重试不重复写；命令和结果未知操作的审批、防重放合同继续验证。

真实付费模型账号的额度、价格、模型效果，以及客户远程主机、客户 Office 环境和具体语音质量，没有用你的 Key 或私人资料进行验证。不能把本机模拟服务验收当作这些外部服务已经验收。

安装文件最终核对：目录共 16,920 个文件，其中 16,919 个载荷文件与发布清单中的字节数、SHA-256 全部一致，另一个文件为清单本身。实际前端与本轮全新构建文件逐项一致；旧前端构建产物未重复保留，安装目录没有混入本轮测试资料、数据库、日志、截图或构建缓存。

内容去重扫描发现 1,489 组相同字节的文件。相同字节不等于可以直接删除：独立程序管理器、后端及子智能体运行环境按各自路径加载依赖，许可证也需要随对应第三方组件保留。本轮没有以全局哈希去重的方式删这些运行文件；清理范围为已被替换的前端产物和本次临时安装文件。
